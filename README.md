# Музыкальный стриминговый сервис

## Описание проекта

Веб-приложение «Музыкальный стриминговый сервис» предназначено для управления музыкальной библиотекой, исполнителями, пользователями и плейлистами.

Приложение предоставляет интерфейс для просмотра и управления основными сущностями музыкального сервиса. Пользователи системы представлены в базе данных, а музыкальные композиции могут объединяться в плейлисты.

## 🛠 Используемые технологии

- **Java** — основной язык разработки.
- **Maven** — управление зависимостями и сборка проекта.
- **PostgreSQL** — реляционная система управления базами данных.
- **GlassFish** — сервер приложений для развёртывания веб-приложения.
- **JPA (Jakarta Persistence)** — взаимодействие с базой данных и управление сущностями.
- **EJB (Enterprise JavaBeans)** — реализация бизнес-логики с использованием Stateless Session Beans.
- **JDBC** — технология взаимодействия с базой данных.
- **HTML / CSS / JavaScript** — разработка пользовательского интерфейса.

## 📌 Функциональные возможности

В приложении реализованы отдельные страницы для работы с основными сущностями:

- **Исполнители** — просмотр, добавление, редактирование и удаление информации об исполнителях.
- **Песни** — управление музыкальными композициями, просмотр информации о треках и их исполнителях.
- **Пользователи** — просмотр и управление зарегистрированными пользователями.
- **Плейлисты** — создание, редактирование и удаление плейлистов, управление входящими в них композициями, переход к конкретному плейлисту.

## Структура базы данных

Для хранения информации используется PostgreSQL.

База данных состоит из пяти основных таблиц:

### 1. Artist (Исполнители)

| Поле | Тип данных | Описание |
|---|---|---|
| artist_id | SERIAL | Первичный ключ |
| name | VARCHAR(120) | Имя исполнителя |
| country | VARCHAR(100) | Страна исполнителя |
| monthly_listeners | BIGINT | Количество ежемесячных слушателей |

### 2. Track (Песни)

| Поле | Тип данных | Описание |
|---|---|---|
| track_id | SERIAL | Первичный ключ |
| title | VARCHAR(120) | Название композиции |
| duration_sec | INT | Продолжительность в секундах |
| play_count | BIGINT | Количество прослушиваний |
| artist_id | INT | Внешний ключ исполнителя |

Каждая песня связана с одним исполнителем.

### 3. App_user (Пользователи)

| Поле | Тип данных | Описание |
|---|---|---|
| user_id | SERIAL | Первичный ключ |
| username | VARCHAR(60) | Имя пользователя |
| email | VARCHAR(120) | Электронная почта |
| registered_at | DATE | Дата регистрации |

Поля username и email должны быть уникальными.

### 4. Playlist (Плейлисты)

| Поле | Тип данных | Описание |
|---|---|---|
| playlist_id | SERIAL | Первичный ключ |
| user_id | INT | Внешний ключ пользователя |
| title | VARCHAR(120) | Название плейлиста |

Каждый плейлист принадлежит одному пользователю.

### 5. Playlist_track (Связь песен и плейлистов)

| Поле | Тип данных | Описание |
|---|---|---|
| playlist_id | INT | Внешний ключ плейлиста |
| track_id | INT | Внешний ключ песни |

Таблица реализует связь многие-ко-многим между плейлистами и песнями. Составной первичный ключ образован полями playlist_id и track_id.

### Связи между сущностями

- Один исполнитель может иметь несколько песен (1:N).
- Один пользователь может создавать несколько плейлистов (1:N).
- Один плейлист может содержать несколько песен.
- Одна песня может входить в несколько плейлистов (M:N).

## ⚙️ Архитектура приложения

Для разделения бизнес-логики и взаимодействия с базой данных используются сервисные классы.

Основные сервисы:

- `ArtistService` — управление исполнителями.
- `TrackService` — управление музыкальными композициями.
- `UserService` — управление пользователями.
- `PlaylistService` — управление плейлистами и связями между плейлистами и песнями.
